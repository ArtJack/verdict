## Findings

### VERDICT-F-1 — Scope guards resolve paths without following symlinks; a symlink inside `.qa/` escapes the QA root

- **Severity:** Major · **Priority:** P1 · **Status:** NEW · **Classification:** n/a (design defect, not a test failure)
- **Location:** `hooks/qa_paths.py:20-27` (`is_allowed_path`), consumed by
  `hooks/enforce_write_scope.py:54` and `hooks/enforce_bash_scope.py:90`.
- **Cause:** the predicate uses `os.path.abspath`, which does **not** resolve symlinks
  (`os.path.realpath` does). A path whose textual form contains a `.qa` component is
  allowed even when it is a symlink pointing at source code outside the QA root.
- **Evidence** — fixture built in a scratch dir, `<scratch>/proj/.qa/pwn` symlinked to
  `<scratch>/proj/src/app.py`, then fed to the guard on stdin:

```
write-guard exit=0 (0=ALLOWED,2=blocked)
```

  Exit 0 means the write is permitted. The target resolves to `proj/src/app.py`, production
  code. `normpath` correctly defeats the `..` traversal case (covered by
  `tests/test_hooks.py::test_write_blocks_qa_traversal_escape`), but symlinks are a
  separate mechanism and are unguarded.
- **Why this is an oversight rather than a decision:** the MCP server defends against
  exactly this attack on its read path —
  `tests/test_mcp_tools.py:234::test_get_report_rejects_symlink_escape`. The write path,
  which is the higher-stakes direction, has no equivalent test. The defense is asymmetric.
- **Both guards affected:** `enforce_bash_scope.py` imports the same predicate
  (line 36), so a shell redirect through a `.qa/` symlink has the same hole.
- **Missing test (specification, for the implementer):**
  `test_write_blocks_symlink_escape_from_qa` — create `tmp_path/.qa/link` symlinked to
  `tmp_path/src/app.py`, assert the guard returns `2` under `VERDICT_STRICT=1`; mirror it
  for the bash guard with a redirect. Guard with `pytest.skip` when symlinks are
  unavailable, matching the existing MCP test's platform handling at
  `tests/test_mcp_tools.py:241`.

### VERDICT-F-2 — The self-gating workflow reads `.qa/` state that is not tracked by git; PR runs will exit 4

- **Severity:** Major · **Priority:** P2 · **Status:** NEW · **Classification:** n/a
- **Location:** `.github/workflows/qa-gate.yml` (untracked), `action.yml` gate mode.
- **Evidence:** `git status --porcelain .qa .github` returned:

```
?? .github/workflows/qa-gate.yml
?? .qa/
```

  The workflow's own comment states the gate "reads the committed `.qa/` state". Nothing
  under `.qa/` is committed, so `actions/checkout` produces a workspace with no state and
  the gate takes the no-state path (`gate.py:55`, `exit_code 4`). `.gitignore` does not
  exclude `.qa/`, so this is an un-committed baseline rather than a config error — this
  run supplies the missing state, but **committing it is a maintainer action, not mine.**
- **Second-order risk:** `max-age-hours: 240` means that once committed, this state stops
  gating after 10 days unless refreshed by a real run. A forgotten state then becomes exit 5
  (stale), which is the correct behaviour — noted so it is not mistaken for a break.

### VERDICT-F-3 — CI's suite command produces no countable summary line (`-q` in addopts plus `-q` on the command line equals `-qq`)

- **Severity:** Minor · **Priority:** P2 · **Status:** NEW · **Classification:** n/a
- **Location:** `pyproject.toml` `[tool.pytest.ini_options] addopts = "-q"` combined with
  `.github/workflows/ci.yml` `uv run --group dev python -m pytest tests/ -q`.
- **Evidence:** piping the CI command's output through `grep -cE "[0-9]+ passed"` returned
  `0`. The CI log shows progress dots and no `106 passed` line. Dropping the redundant `-q`
  restores it. The same doubling breaks ID collection: `--collect-only -q` printed per-file
  *counts* (`tests/test_score.py: 21`) instead of test IDs, so the naive collection command
  yields zero parseable IDs.
- **Why it matters here specifically:** this repo's own agent contract (§6, §9) requires
  set-diff accounting over test IDs and warns that "a green with no countable summary line
  is not a countable green". The project's CI currently violates the rule the project
  ships. `-o addopts=` is the workaround, now recorded in the profile.

### VERDICT-F-4 — Orphaned `.qa/test-ids.txt` with no `state.json`

- **Severity:** Minor · **Priority:** P3 · **Status:** NEW · **Classification:** n/a
- **Evidence:** before this run, `.qa/` contained exactly one file, `test-ids.txt`
  (106 lines), and no `state.json`. An aborted or partial prior run left a ledger behind.
- **Impact:** benign this time — the orphan ledger was byte-identical to this run's
  collection, so no phantom delta was produced. Had the suite changed in between, run 2
  would have diffed against a ledger no state file accounted for and mis-attributed the
  change. Closed by this run writing a matching `state.json`.

## Findings (by severity, REGRESSED first)

### PRICER-F-003 — REGRESSED — Critical / P0 — REAL_DEFECT
`round_cents` uses banker's rounding, not half-up (spec rule 3).
- `pricer.py:16-18` — `return round(amount, 2)`.
- `README.md` rule 3: "cent rounding is half up — `0.125` rounds to `0.13`".
- Evidence: `python3 -c "print(round(0.125,2))"` -> `0.12`; also `round(0.135,2)` ->
  `0.14`, `round(2.675,2)` -> `2.67`. Test `test_round_cents_half_up` (test_pricer.py:30)
  fails: `assert 0.12 == 0.13`.
- Delta: state.json marked this RESOLVED in run 2 ("round_cents rewrote to half-up").
  The `git diff 8d0f3fa..HEAD` does not touch `round_cents`, so the code at run 2's own
  SHA already failed this test. The run-2 resolution was not real. First seen 2026-08-20,
  age 8 days.
- Impact: systematic sub-cent error on every `net_proceeds` and `bulk_unit_price`
  result whose exact value lands on a half-cent.
- Fix: implement half-up rounding (e.g. `decimal.Decimal` with `ROUND_HALF_UP`, or
  `math.floor(amount*100 + 0.5)/100` with documented float caveats). Do not fix by
  editing the test.

### PRICER-F-008 — NEW — Critical / P1 — REAL_DEFECT
`bulk_unit_price` denies the bulk discount to orders of exactly 10 units.
- `pricer.py:30` — `if qty > 10:` (was `if qty >= 10:` at sha 8d0f3fa).
- `README.md` rule 4: "orders of **10 or more** units get 10% off the unit price".
- Evidence: `bulk_unit_price(20.0, 9)` -> `20.0`; `bulk_unit_price(20.0, 10)` -> `20.0`
  (should be `18.0`); `bulk_unit_price(20.0, 11)` -> `18.0`. Introduced by commit
  6299859. Breaks two tests:
  - `test_bulk_discount_applies` (test_pricer.py:35): `assert 20.0 == 18.0`.
  - `test_bulk_orders_fixture` (test_pricer.py:49) on row
    `{"price":20.00,"qty":10,"expected":18.00}`: `assert 20.0 == 18.0`.
- Classification: REAL_DEFECT. Both test expectations match the spec ("10 or more");
  the CHANGELOG "2026-08-30" entry describes only test maintenance, giving no intended
  -change citation for the threshold. Not a STALE_EXPECTATION.
- Severity note: Critical because it is a freshly shipped regression producing wrong
  customer-facing pricing on a documented boundary and it reddens the blocking gate.
  Would drop to Major given evidence that exactly-10-unit orders carry negligible
  volume/revenue.
- Fix: restore `if qty >= 10:`. Add an explicit boundary test at qty = 9 / 10 / 11
  (see Test scenarios).
